## Directory Purposes

**src/ (Python Backend):**
- Purpose: Device-local AI agent that executes voice commands
- Contains: Command orchestration, AI brain, system execution, database sync
- Key files: `main.py` (entry), `brain.py` (AI), `executor.py` (actions), `database.py` (sync)

**app/lib/ (Flutter Frontend):**
- Purpose: Mobile voice interface for user interaction
- Contains: UI screens, state management, platform services (TTS, STT)
- Key files: `main.dart` (entry), `controllers/miva_controller.dart` (state)

**app/lib/controllers/ (State Management):**
- Purpose: GetX reactive state binding mobile UI to Supabase streams
- Contains: Speech recognition lifecycle, command submission, response streaming
- Key files: `miva_controller.dart` (single controller managing all mobile state)

**app/lib/ui/screens/ (Screens):**
- Purpose: Presentational layer for voice interaction
- Contains: Voice button, response display, status indicators, glitch effects
- Key files: `home_screen.dart` (single-screen app)

**app/lib/core/config/ (Configuration):**
- Purpose: Static configuration and credentials
- Contains: Supabase endpoint and anon key
- Key files: `supabase_config.dart` (hardcoded Supabase credentials)

**app/lib/core/services/ (Platform Services):**
- Purpose: Wrappers around platform-specific capabilities
- Contains: Text-to-speech integration
- Key files: `tts_service.dart` (singleton TTS manager with Vietnamese voice)

**.planning/codebase/ (This Directory):**
- Purpose: Architecture documentation generated by GSD tools
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md
- Generated: Yes, committed: Yes

## Naming Conventions

**Files:**
- Python: `snake_case.py` (e.g., `main.py`, `database.py`, `executor.py`, `brain.py`)
- Dart: `snake_case.dart` (e.g., `home_screen.dart`, `miva_controller.dart`, `supabase_config.dart`)
- Flutter packages: `[package_name]_[type].dart` (e.g., `miva_controller.dart` for controller)

**Directories:**
- Feature-based grouping: `controllers/`, `ui/`, `core/`, `services/`, `config/`, `screens/`
- Python flat structure: All modules in `src/` root (no subdirectories)

**Classes & Types:**
- Python: PascalCase (e.g., `MivaCore`, `MivaBrain`, `ActionExecutor`, `DatabaseManager`)
- Dart: PascalCase (e.g., `MivaController`, `HomeScreen`, `MivaApp`, `TtsService`)

**Functions & Methods:**
- Python: camelCase (e.g., `ask()`, `run_terminal()`, `handle_new_command()`)
- Dart: camelCase (e.g., `startListening()`, `stopListening()`, `_sendCommand()`)

**Variables & Properties:**
- Python: snake_case (e.g., `command_id`, `input_text`, `action_to_run`)
- Dart: camelCase (e.g., `isListening`, `speechText`, `aiResponse`, `isProcessing`)
- Dart observables (GetX): Suffix with `.obs` (e.g., `isListening.obs`, `aiResponse.obs`)

## Where to Add New Code

**New Feature (e.g., new command type):**
- Primary code: Add handler method to `ActionExecutor` in `src/executor.py`
- Backend logic: Extend `MivaBrain` system prompt in `src/brain.py` to teach intent recognition
- Mobile UI: Modify `HomeScreen._buildAIResponseBox()` in `app/lib/ui/screens/home_screen.dart` if new visualization needed
- Tests: Create `src/test_executor.py` (not currently implemented)

**New Component/Module (e.g., device management, auth):**
- Implementation: Create new Python file in `src/` (e.g., `src/device_manager.py`)
- Mobile: Create new Dart file in `app/lib/controllers/` or `app/lib/core/services/`
- Integration: Wire into `MivaCore.__init__()` (line 9-12) for backend
- Integration: Wire into `MivaController` or create new GetX controller for mobile

**Utilities:**
- Shared helpers (Python): Add to `src/executor.py` or create `src/utils.py`
- Shared helpers (Dart): Add to existing `TtsService` or create `app/lib/core/services/utils.dart`

**Constants:**
- Python: Define at module top level (e.g., `ALLOWED_TERMINAL_COMMANDS` dict in `src/executor.py` line 7-14)
- Dart: Use static const in config file or separate `constants.dart`

## Architecture Patterns by Directory

**Python Backend (src/):**
- **Pattern**: Layered architecture with async event-driven coordination
- **Dependency Flow**: MivaCore (top) → DatabaseManager + MivaBrain + ActionExecutor (middle layer) → External APIs/OS (bottom)
- **Module Responsibilities**:
  - `main.py`: Orchestration and lifecycle management
  - `database.py`: Data access abstraction
  - `brain.py`: External API integration (Groq)
  - `executor.py`: System capability abstraction

**Flutter Mobile (app/lib/):**
- **Pattern**: MVC with GetX state management
- **Dependency Flow**: HomeScreen (view) → MivaController (controller) → Supabase + STT/TTS services (data layer)
- **Directory Organization**: Feature-based (controllers, ui, core services, config)

## Code Organization Principles

1. **Single Responsibility**: Each Python module handles one concern (brain, execution, database, orchestration)
2. **Separation of Concerns**: UI (Dart) is completely decoupled from execution logic (Python) via Supabase
3. **Async-First**: Python backend uses asyncio for non-blocking I/O
4. **Reactive UI**: Dart mobile uses GetX observables for reactive state binding
5. **Whitelist Security**: System execution is restricted to allowed commands only
6. **Stateless Processing**: Each command is independent (except 10-message history in brain)
